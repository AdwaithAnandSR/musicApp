130     ## 3. Expo Widgets — Can You Build an Android
          Widget?
  131
  132     ### Yes, you can. Here's the status:
  133
  134     expo-widgets has full Android support in SDK 58.
          From the changelog, Android support was
          introduced in SDK 57/58 with:
  135
  136     • ✅ React-rendered Android widgets (via Jetpack
          Glance under the hood)
  137     • ✅ Image component support
  138     • ✅ cornerRadius modifier
  139     • ✅ Material Colors support
  140     • ✅ Interactions (button taps → JS callbacks via
          addUserInteractionListener)
  141     • ✅ Timeline updates (updateTimeline,
          updateSnapshot)
  142     • ✅ Fix for Glance session updates
  143     • ✅ Widget configuration enums
  144     • ✅ Shared directory for widget images
          (widgetsDirectory)
  145
  146     ### What a music widget could look like
  147
  148     You could create a widget showing:

  149     • Current track info (title, artist, artwork)
  150     • Play/pause button (via
          addUserInteractionListener)
  151     • Next/prev buttons (also via interaction
          listener)
  152
  153     ### How it works
  154
  155     1. Define a widget component using the 'widget'
          directive
  156     2. Configure in app.json under expo-widgets
          plugin
  157     3. Create the widget with createWidget(name,
          component, initialProps)
  158     4. Update it with widget.updateSnapshot({ title,
          artist, artwork }) whenever the track changes
  159     5. Handle taps with addUserInteractionListener()
          → call your Zustand store's next(), prev(),
          playPause()
  160
  161     ### Limitations to know
  162
  163     │ Note
          │
  164     │ • Widget UI is not standard React Native views
          —
          │ it's rendered through Jetpack Glance (Android)
          /
          │ WidgetKit (iOS). You use @expo/ui components,
          │ not <View>, <Text>, etc.
  165     │ • The widget cannot directly read Zustand state
          │ — it runs in a separate process. You must push
          │ state to the widget via updateSnapshot().
  166     │ • Network images in widgets require using the
          │ shared widgetsDirectory — you'd download
          artwork
          │ there first.
  167     │ • Live Activities (Dynamic Island) are iOS only
          │ — not relevant for Android widgets.
  168     │ • You already have "expo-widgets" in your
          │ plugins array in app.json, so the config plugin
          │ is already set up.
  169
  170     ### Next steps for widgets
  171
  172     1. Create a widget layout file (e.g.,
          src/widgets/MusicWidget.tsx) with the 'widget'
          directive
  173     2. Add widget configuration to app.json (name,
          sizes, description)
  174     3. Create an @expo/ui based layout for the widget
  175     4. Wire up updateSnapshot() in your player store
          to push track metadata on every track change
  176     5. Wire up addUserInteractionListener() to handle
          play/pause/next/prev taps
